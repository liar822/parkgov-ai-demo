# AI 智慧停车平台正式部署指南

本文档用于把当前本地原型部署为稳定公网演示版本。推荐组合：

- 前端：Vercel
- 后端：Render
- 数据库：Neon PostgreSQL

该部署仍是挑战杯 MVP 演示环境，不代表接入全北京真实摄像头或真实停车场生产系统。

## 1. 准备 Git 仓库

Render 和 Vercel 都建议从 GitHub 仓库部署。不要直接推到原作者仓库 `yashkusumkar02/ai-parking-system`，应先创建我们自己的项目仓库，然后推送当前二次开发代码。

建议仓库名：

```bash
parkgov-ai-smart-parking
```

## 2. 创建 Neon 数据库

1. 打开 Neon 控制台并创建一个 PostgreSQL 项目。
2. 创建数据库，例如 `parkgov_ai_parking`。
3. 复制连接串，格式类似：

```bash
postgresql://USER:PASSWORD@HOST.neon.tech/DATABASE?sslmode=require
```

后端已支持 `DATABASE_URL` 和 SSL，适合 Neon / Supabase。

## 3. 部署后端到 Render

仓库根目录已经新增 `render.yaml`。在 Render 中选择 Blueprint 部署，指向当前 GitHub 仓库。

Render 后端服务关键配置：

- Root Directory: `backend`
- Build Command: `npm ci`
- Start Command: `npm start`
- Health Check Path: `/api/health`

需要在 Render 环境变量中填写：

```bash
DATABASE_URL=你的 Neon PostgreSQL 连接串
DATABASE_SSL=true
FRONTEND_URLS=https://你的-vercel-前端域名
JWT_SECRET=一个足够长的随机字符串
NODE_ENV=production
PYTHON_PATH=python3
```

第一次部署后，打开：

```bash
https://你的-render-backend.onrender.com/api/health
```

看到 `status: OK` 即后端启动成功。

## 4. 初始化演示数据

后端启动时会自动建表并写入最基础示例数据。要恢复当前挑战杯 MVP 演示数据，需要在 Render Shell 或本地连接云数据库后执行：

```bash
cd backend
npm run seed:mvp
```

如果只想检查数据库建表脚本：

```bash
npm run check:db-init
```

如果要检查线上 API：

```bash
API_BASE_URL=https://你的-render-backend.onrender.com/api npm run check:api
```

## 5. 部署前端到 Vercel

前端目录已经新增 `frontend/vercel.json`。在 Vercel 中导入同一个 GitHub 仓库，并设置：

- Framework Preset: Vite
- Root Directory: `frontend`
- Build Command: `npm run build`
- Output Directory: `dist`

Vercel 环境变量：

```bash
VITE_API_URL=https://你的-render-backend.onrender.com/api
```

部署完成后得到：

```bash
https://你的-vercel-前端域名.vercel.app
```

然后回到 Render，把 `FRONTEND_URLS` 更新为该 Vercel 域名。

## 5.1. Netlify 备选

如果不用 Vercel，也可以把前端部署到 Netlify。前端目录已经新增 `frontend/netlify.toml`。

Netlify 配置：

- Base directory: `frontend`
- Build command: `npm run build`
- Publish directory: `frontend/dist`

Netlify 环境变量同样填写：

```bash
VITE_API_URL=https://你的-render-backend.onrender.com/api
```

部署完成后，也需要把 Netlify 域名加入 Render 的 `FRONTEND_URLS`。

## 7. 当前部署边界

- 当前是挑战杯 MVP 演示，不是生产级全北京系统。
- 不接真实摄像头网络。
- 不做车牌识别。
- 不采集个人信息。
- 北京公共停车数据和校园数据仍以 demo / 样例 / 模板方式展示。
- AI 数据集验证结果用于说明识别链路，不等于真实停车场实时余位。

## 8. 后续可升级

- 将 Render Free 升级为付费实例，减少冷启动。
- 将 Neon Free 升级为更高配数据库。
- 增加正式域名，例如 `parking.example.com`。
- 将 `seed:mvp` 改成受保护的后台初始化任务。
- 对管理端增加更严格的账号和权限模型。
